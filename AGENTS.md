# viclafouch/skills

The skills behind how Victor works, for every project he opens: a company monorepo, a personal app, an open-source library, a repository with one commit.

## Any project

Each skill serves a project it does not know. The projects in use today are samples of that public:

- A skill reads what the project has and works with it: its docs, its labels, its milestones, its tracker, its package manager, its language. Any of them may be missing.
- The project's own conventions and rules carry the opinions. A skill brings the steps and their finish line.
- When the project lacks what a step needs, the skill asks.
- A skill names no project, company, product or person.

Before a change lands, run it in your head on other projects: a repository with no milestone and only the default labels, a project with no `AGENTS.md`, a team on Linear, a monorepo, a solo side project.

## Writing a skill

Short and plain: what to do, in order, and when each step is done. Run `mattpocock-skills:writing-for-agents` before you create or edit one.
